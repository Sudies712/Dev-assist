# 接口字段契约

> 依据：需求规格说明书 V2.1 §14 接口清单 / §7 数据字典；概要设计 V1.1 §6 接口设计
> 用途：前后端协作的请求/响应字段约定。SRS §14 已定义全部路径（共 74 个），本文档只补充**字段级契约**：通用规范 + 关键/有状态接口的 DTO；普通 CRUD 接口的字段即 §7 实体字段 + 审计字段，不再重复。

---

## 1. 通用规范

### 1.1 统一响应

```json
// 普通响应
{ "code": 200, "message": "ok", "data": <T> }

// 分页响应
{ "code": 200, "message": "ok",
  "data": { "list": [<T>], "total": 100, "pageSize": 20, "currentPage": 1 } }
```

### 1.2 状态码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 401 | 未登录 / Token 失效 |
| 403 | 无权限 |
| 400 | 参数校验错误（message 含字段明细） |
| 500 | 服务端错误 |
| 50001 | 账号已锁定（登录） |
| 50002 | 账号已禁用 |
| 50003 | 乐观锁冲突（并发修改，请刷新重试） |
| 50004 | 状态流转非法（不符合状态机） |
| 50005 | AI 服务不可用 |

### 1.3 鉴权
- 除 `POST /api/login`、`POST /api/refresh-token` 外，所有请求头携带 `Authorization: Bearer <accessToken>`
- 401 时前端用 refreshToken 静默刷新后重放

### 1.4 SSE 流式（AI 助手 + 知识库问答）
- 响应头 `Content-Type: text/event-stream`
- 每事件：`data: {json}\n\n`，末尾 `data: [DONE]\n\n`
- 统一事件结构：

```json
{ "type": "delta",  "content": "流式片段文本" }
{ "type": "done",   "items": [<结构化建议>], "aiRecordId": 123 }
{ "type": "sources","items": [{ "docName":"...", "snippet":"..." }] }   // 仅知识库问答
{ "type": "error",  "message": "..." }
```

### 1.5 通用 VO 字段约定
所有业务实体返回时附带：`id`、`createTime`、`updateTime`、`createBy`、`version`。枚举字段返回**英文码**（如 `PENDING_REVIEW`），前端按 §7.11 枚举本地化展示。

## 2. 认证模块

### POST /api/login
请求：
```json
{ "username": "admin", "password": "明文" }
```
响应 `data`：
```json
{
  "accessToken": "...", "refreshToken": "...", "expires": 7200,
  "user": {
    "id": 1, "username": "admin", "realName": "系统管理员", "avatar": null,
    "roles": ["ADMIN"],
    "permissions": ["menu:dashboard", "user:create", "..."]
  }
}
```

### POST /api/refresh-token
请求 `{ "refreshToken": "..." }` → 响应同 login 的 token 部分。

### PUT /api/users/change-password
请求 `{ "oldPassword": "...", "newPassword": "..." }` → `data: true`

### GET /api/users/profile → `data`：UserVO
### PUT /api/users/profile
请求 `{ "realName", "email", "phone", "avatar" }`

## 3. 状态机类接口（核心）

> 状态变更统一语义：请求体带 `targetStatus` + 可选业务字段；后端按 SRS 状态机校验合法性，非法返回 `50004`。

### PUT /api/requirements/{id}/status
```json
{ "targetStatus": "CONFIRMED", "reviewResult": "PASS", "reviewOpinion": "评审通过" }
```
- `reviewResult`/`reviewOpinion` 仅 `PENDING_REVIEW → CONFIRMED/CLOSED` 时必填（写评审记录）
- 排期状态 `SCHEDULED` 由排期接口联动，不在此直接切换

### POST /api/requirements/{id}/schedule  （加入迭代）
```json
{ "sprintId": 10 }
```
→ 后端：写 `sprint_requirement`、需求状态置 `SCHEDULED`。
### DELETE /api/requirements/{id}/schedule?sprintId=10 → 状态退回 `CONFIRMED`

### PUT /api/tasks/{id}/status
```json
{ "targetStatus": "IN_PROGRESS", "reason": "退回原因（仅退回必填）" }
```
- `IN_PROGRESS → TODO` 退回须填 `reason`
- `READY_FOR_TEST → DONE/IN_PROGRESS` 由测试人员或开发人员操作

### PUT /api/bugs/{id}/status
```json
{ "targetStatus": "FIXING", "fixDescription": "修复说明（→PENDING_VERIFY 必填）", "failReason": "验证失败原因（PENDING_VERIFY→PENDING_FIX 必填）", "rejectReason": "拒绝原因（→REJECTED 必填）" }
```

### PUT /api/bugs/{id}/assign
```json
{ "assigneeId": 5 }
```

### POST /api/test-cases/{id}/execute
```json
{ "sprintId": 10, "actualResult": "实际结果描述", "result": "PASSED" }
```
- `result`：`UNEXECUTED/PASSED/FAILED/BLOCKED/SKIPPED`
- `FAILED` 时前端可附带 `submitBug: true` 一并创建 Bug（后端联动建 Bug 并关联当前需求/迭代）

## 4. 文档与知识库

### POST /api/documents （multipart/form-data）
| 字段 | 说明 |
|------|------|
| file | 文件（MD/TXT，≤10MB）|
| projectId | 所属项目 |
| name | 文档名称 |
| type | 文档类型码 |
| description | 描述（可选）|

→ `data: DocumentVO`；上传成功后异步触发解析（`parseStatus` 经历 `UNPARSED→PARSING→PARSED/FAILED`）。

### GET /api/documents/{id}/download → 二进制流（`Content-Disposition: attachment`）

### POST /api/documents/{id}/reparse → 重新触发解析（失败后可调用）

### POST /api/projects/{id}/kb/ask （SSE）
请求 `{ "question": "用户问题" }`
事件流：
```
data: {"type":"delta","content":"回答片段..."}
data: {"type":"sources","items":[{"docName":"接口文档","snippet":"..."}]}
data: {"type":"done","aiRecordId":88}
data: [DONE]
```

## 5. AI 助手与草稿

### POST /api/ai/{assistant} （SSE，assistant ∈ requirement-analysis/task-breakdown/test-case-generation/bug-analysis/sprint-summary/project-summary）
请求：
```json
{ "projectId": 1, "contextId": 123 }
```
- `contextId`：需求 id / 迭代 id / Bug id（按助手类型语义不同）
事件流：`delta`（流式文本）→ `done`（结构化建议 + aiRecordId）

`done.items` 元素结构（建议项，供采纳）：
```json
{ "targetModule": "TASK", "targetType": "BACKEND", "title": "建议标题", "content": "建议正文", "priority": "HIGH" }
```
- `targetModule`：`REQUIREMENT/TASK/TESTCASE/BUG/SPRINT_SUMMARY/PROJECT_SUMMARY`（一次生成可含多种）

### POST /api/ai/drafts （采纳选中，生成草稿）
```json
{ "aiRecordId": 88, "projectId": 1,
  "items": [ { "targetModule":"TASK", "targetType":"BACKEND", "content":"{...}" } ] }
```
→ `data: { "draftIds": [201, 202] }`，草稿状态 `PENDING_CONFIRM`

### PUT /api/ai/drafts/{id}/confirm （二次确认，事务转写正式表）
→ `data: { "targetId": 301 }`（生成的业务实体 id）；草稿状态置 `ADOPTED`
- 后端按 `targetModule` 分发到对应 Service 创建方法，事务保证

### DELETE /api/ai/drafts/{id} → 状态置 `DISCARDED`

## 6. 统计接口

### GET /api/projects/{id}/statistics → `data`
```json
{
  "project": { "total": 5, "inProgress": 2, "statusDist": [{"status":"IN_PROGRESS","count":2}] },
  "requirement": { "total": 30, "doneRate": 0.6, "priorityDist": [{"priority":"HIGH","count":8}] },
  "task": { "total": 80, "doneRate": 0.5, "byAssignee": [{"userId":3,"count":12}] },
  "bug": { "total": 15, "severityDist": [{"severity":"CRITICAL","count":1}], "statusDist": [] },
  "test": { "total": 40, "passRate": 0.85, "resultDist": [{"result":"PASSED","count":34}] },
  "ai": { "totalCalls": 120, "adoptRate": 0.7, "byType": [{"aiType":"TASK_BREAKDOWN","count":50}] }
}
```

### GET /api/sprints/{id}/burndown → `data`
```json
{ "days": ["D1","D2",...], "ideal": [20,17,14,...], "actual": [20,18,15,...] }
```
- 纵轴单位：**剩余任务数**（依据 SRS §5.4.4）

### GET /api/projects/{id}/member-load → `data`
```json
[ {"userId":3,"realName":"张三","taskCount":5,"bugCount":2,"doneCount":3} ]
```

## 7. 普通 CRUD 约定

需求/任务/Bug/测试用例/文档等列表与详情接口，字段直接对应 §7 实体：
- 列表 `GET /api/...` 支持查询参数 `projectId/sprintId/status/assigneeId/page/pageSize`，返回 `PageResult<实体VO>`
- 详情 `GET /api/.../{id}` 返回实体 VO（含关联展示字段，如任务的 `assigneeName`、需求的 `sprintId`）
- 创建/编辑的请求体 = 实体业务字段子集（不含 `id/审计字段/version`）

> 字段命名：后端 Java 驼峰（`projectId`）经 Jackson 序列化为 JSON；数据库 snake_case 由 MyBatis-Plus mapUnderscoreToCamelCase 映射。

## 8. 项目成员接口守卫约定

`POST /api/projects/{id}/members`（添加成员）、`PUT /api/projects/{id}/members/{userId}/role`（修改角色）、`DELETE /api/projects/{id}/members/{userId}`（移除成员）：

- `projectRole` 仅允许 `OWNER` / `DEVELOPER` / `TESTER`，非法值返回 `400`，message 含"未知的项目角色"
- 项目必须始终保留至少 1 名负责人（OWNER）：降级最后一名 OWNER 或将其移除，返回 `400`，message 含"至少需保留 1 名项目负责人"
- 提升其他成员为 OWNER 不受限（这是项目恢复有主状态的正确路径）
- 移除不存在成员返回 `404`（原实现为静默删除，现已修正）
